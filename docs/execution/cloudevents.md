# Recognition CloudEvents contract

Status: **frozen 1.0.0** — ADR 0010 / ADR 0015 (`ytci-mobile`, branch `docs/mice-gamification-decisions`)
Owner: `stream:recognition`
Machine-readable mirror: `api/contracts/cloudevents.v1.yaml`
Database registry: `recognition.event_types` (migration 0030)
Contract tests: `internal/contracts/cloudevents_test.go`

This is the one canonical document for recognition events. Every emitter,
consumer, test fixture and admin screen uses the names and rules here. The YAML
mirror is the same contract in executable form; CI fails if the two drift.

## 1. Envelope

Recognition uses a CloudEvents-shaped envelope without a broker. The emitter
writes the event in the same database transaction as the source change, then an
outbox worker evaluates rules.

```json
{
  "specversion": "1.0",
  "id": "01927f3e-9f7a-7c3a-9d2f-2f0f6f1a8b11",
  "source": "ke.events.api",
  "type": "ke.event.attended.v1",
  "subject": "reader_01HX…",
  "time": "2026-11-19T08:12:00Z",
  "data": {
    "source_type": "event",
    "source_id": "11111111-1111-4111-8111-111111111111",
    "occurrence_key": "event.attendance:11111111-1111-4111-8111-111111111111",
    "verification_method": "staff_scan",
    "verification_result": "verified",
    "sensitivity": "standard",
    "privacy_class": "private",
    "age_band": "18_plus",
    "program_scope": "ytci",
    "consent_version": "2026-11-01",
    "occurred_at": "2026-11-19T08:12:00Z",
    "source_revision": 1
  }
}
```

| Field | Rule |
|---|---|
| `specversion` | Always `1.0`. |
| `id` | UUIDv7 generated by the emitter. Also the transport `Idempotency-Key`. |
| `source` | Emitting module, `ke.<domain>.<module>`; stable per emitter. |
| `type` | One of the frozen names below. |
| `subject` | Reader subject id. Never a name, email, phone, county or analytics id. |
| `time` | Occurrence time in UTC. |
| `data` | Allow-listed payload only; unknown fields are rejected. |

## 2. Event names, rewards and verification

| Event type | Subject | Reward | Badge | Accepted verification | Privacy |
|---|---|---|---|---|---|
| `ke.heritage.visit.verified.v1` | site | 100 XP | `heritage_site_visit` | GPS / QR / manual code | private, public, sensitive |
| `ke.heritage.trail.completed.v1` | trail | 250 XP | `heritage_trail_complete` | GPS / QR / manual code | private, public, sensitive |
| `ke.heritage.county.collected.v1` | county | 150 XP | `county_collected` | GPS / QR / manual code | private, public |
| `ke.conservation.participation.verified.v1` | activity | 150 XP | `conservation_participant` | staff scan / moderation | private, public |
| `ke.challenge.completed.v1` | challenge | 50 / 100 / 150 XP by difficulty | `challenge_complete` | moderation | private, public |
| `ke.course.completed.v1` | course | 150 XP, first pass only | `course_complete` | passed quiz | private, public |
| `ke.event.attended.v1` | event | 50 XP, check-in only | `event_attended` | QR / staff scan | private, public |
| `ke.audio.story.completed.v1` | story | 25 XP, once per story, 5/week cap | `audio_story_complete` | server-recorded | private |
| `ke.community.story.approved.v1` | story | 50 XP, 3/week cap | `community_contributor` | moderation | private, public |
| `ke.explore.destination.progressed.v1` | destination | 0 XP, private progress | none | self-declared | private |
| `ke.season.completed.v1` | season | 500 XP | `season_complete` | server-recorded | private, public |

Additional heritage rewards from ADR 0004 remain in force: optional Trail Stop
(25 XP) and Story cut (20 XP).

Only `verified`, `attested`, `moderated` and `server_recorded` may award XP.
`self_declared` feeds private progress only. `rejected` never awards.

An RSVP, ticket handoff, save, search, alert open or marketplace handoff is not
a recognition event and must not emit one.

## 3. Occurrence keys

An occurrence key is deterministic and scoped to the subject. It identifies the
thing that happened, not the delivery.

| Event type | Template |
|---|---|
| `ke.heritage.visit.verified.v1` | `heritage.site:{site_id}` |
| `ke.heritage.trail.completed.v1` | `heritage.trail:{trail_id}` |
| `ke.heritage.county.collected.v1` | `heritage.county:{county_gid}` |
| `ke.conservation.participation.verified.v1` | `conservation.activity:{activity_id}` |
| `ke.challenge.completed.v1` | `challenge:{challenge_id}` |
| `ke.course.completed.v1` | `course:{course_id}:{revision}` |
| `ke.event.attended.v1` | `event.attendance:{event_id}` |
| `ke.audio.story.completed.v1` | `audio.story:{story_id}` |
| `ke.community.story.approved.v1` | `community.story:{story_id}` |
| `ke.explore.destination.progressed.v1` | `explore.destination:{destination_slug}` |
| `ke.season.completed.v1` | `season:{season_id}` |

Rules:

- A placeholder must be filled; an unfilled key is a bug and the emitter must
  fail the transaction.
- The same subject and occurrence key must always produce the same semantic
  event. Re-emitting with a new `id` is allowed only as at-least-once delivery.
- Course revisions produce a new occurrence (`revision`) but course XP is first
  pass only, so the second revision cannot mint new XP.
- No occurrence key contains a name, email, county name, coordinates or free
  text.

## 4. Award key

An award is uniquely identified by **rule + reader + event**:

```text
award_key = rule_key | subject_id | source_type | source_id
```

Example:

```text
event.attendance|reader_01HX…|event|11111111-1111-4111-8111-111111111111
```

- The rule **version is not part of the key**. Publishing rule v4 cannot mint a
  second award for the same occurrence.
- Badge awards additionally carry `(subject_id, badge_key, source_type,
  source_id)`.
- XP awards carry `(subject_id, rule_key, source_type, source_id)` where
  `reason = 'award'` (partial unique index).
- Corrections are new rows with `reason = 'adjustment'` or `'reversal'`, an
  approver and a note. XP is never edited or deleted.

## 5. Idempotency and delivery

| Rule | Value |
|---|---|
| Delivery | At least once |
| Effect | Exactly once |
| Transport key | `event.id` (UUIDv7) |
| Event uniqueness | `(source, id)` |
| Occurrence scope | `(subject, occurrence_key)` |
| Award uniqueness | `(subject_id, rule_key, source_type, source_id)` and `(subject_id, badge_key, source_type, source_id)` |
| XP uniqueness | `(subject_id, rule_key, source_type, source_id)` where `reason = 'award'` |
| Outbox uniqueness | `(event_id, topic)` |
| Concurrency | `FOR UPDATE SKIP LOCKED` |
| Write pattern | `INSERT … ON CONFLICT DO NOTHING RETURNING id`; update projections only when a row is returned |
| Dedupe window | None; identity is durable |

Outbox processing:

1. Claim due rows with `FOR UPDATE SKIP LOCKED`.
2. Evaluate every published rule effective at `time`.
3. Insert ledger entries and awards with `ON CONFLICT DO NOTHING`.
4. Update `xp_totals`, progress, badges and leaderboard projections only when a
   new row was returned.
5. Mark the outbox row done; failures retry with backoff and then go dead.
6. A nightly reconciliation recomputes `SUM(amount)` and alerts on drift. It
   never auto-corrects.

If a handler crashes after writing the source row but before the outbox row, the
whole transaction rolls back. If the worker crashes mid-batch, retries are safe
because every effect is idempotent.

## 6. Payload allow-list

Allowed fields only:

`source_type`, `source_id`, `occurrence_key`, `verification_method`,
`verification_result`, `sensitivity`, `privacy_class`, `age_band`,
`program_scope`, `consent_version`, `occurred_at`, `source_revision`.

Never in the payload:

`name`, `email`, `phone`, `county`, `latitude`, `longitude`, `coordinates`,
`free_text`, `media_url`, `quiz_answer`, `analytics_id`.

Unknown fields are rejected. Client-supplied sensitivity is rejected; the
server derives privacy class and sensitivity from the source and the site's
classification.

## 7. Verification and anti-abuse boundaries

- Heritage requires foreground GPS (≤ 50 m), a fresh fix, a 150 m default
  geofence, or a single-use QR/manual code. Mocked locations downgrade the
  result.
- Event XP requires a staff or QR check-in, never an RSVP.
- Audio XP is capped at 5 per week and sits behind a kill switch.
- Community stories require moderation plus duplicate-content detection.
- Course XP requires a passed quiz and is once per course.
- Challenge and conservation evidence are moderated and deduped.
- Per-subject, per-source and per-device rate limits raise anomaly alerts.
- Manual adjustments need a second approver; never a self-award.

## 8. Backfill

Backfill is additive only:

- Rules are immutable; a change creates a new version with `effective_from`.
- Replay uses the rule version effective at `occurred_at`.
- Dry run, diff counts, a second approver, rate-limited batches.
- Compensating entries for corrections.
- Never retroactively grant XP for a policy that did not exist when the reader
  acted.

`recognition.backfill_batches` carries `created_by`, `approved_by`, a CHECK that
they differ, and a dry-run diff.

## 9. Versioning and change control

- Event names carry `.v1`. A breaking payload change creates `.v2`; v1 stays
  readable until every consumer has migrated.
- Adding an optional payload field is additive and bumps the contract minor
  version.
- Removing or renaming a field, changing an occurrence key, changing the award
  key or changing verification semantics is breaking and needs a change-control
  ticket (see [contracts.md](contracts.md)).
- The database registry, the YAML mirror, this document and the Go constants
  must change together. `TestCloudEventTypesAreFrozen` enforces the set.
